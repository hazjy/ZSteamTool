# ZSteamTool v1.1.5 —— 联机会话、家庭共享与启动提速

> 适用版本：v1.1.5（对比 v1.1.4）。本说明只列对外可见的改动。

## 一句话

启动提速一个量级；入库游戏的联机改走 Steam 官方大厅；家庭共享的游戏不再被误判；另有一批崩溃与静默失效的修复。

## 必须更新吗

不强制。v1.1.4 在当前的 Steam 客户端上可正常使用。以下情形建议更新：

- 觉得每次启动 Steam 都在等签名表（v1.1.4 在缓存未命中时会走完整镜像链）；
- 用家庭共享的账号玩游戏，遇到过「库里的游戏莫名消失」；
- 想让好友看到你在玩的入库游戏；
- 遇到启动后闪退、票据相关报错（54 / 012 / 05）。

## 新增

- **联机会话（宿主会话）**：`[onlinefix] env_session`，默认开启。由 GUI 的宿主进程给游戏设置会话身份，并让客户端内部对该进程的 appid 判断与会话一致，从而能使用 Steam 官方大厅。旧的 `-onlinefix` 命令行路线仍在。
- **好友广播开关**：`[presence] display`，`"spacewar"`（默认）或 `"none"`。设为 `none` 时跳过全部好友广播改写，仅用于排查。
- **快捷方式富状态**：仅用 addappid 的单机游戏，出站游玩状态改以「非 Steam 游戏」形式广播，好友侧可看到游戏名。
- **家庭共享许可分类**：区分「自己拥有」「家庭共享」「借用」三种来源，不再把借来的游戏记为已拥有。
- **排查脚本**：新增 `tools/diag/`（Steam 更新后的定位链）与 `tools/p2ptest/`（双机 P2P 连通性探针）。

## 改进

- **签名表改为缓存优先**：按客户端 DLL 的 SHA-256 内容寻址，命中即不联网。本机实测启动耗时由 49–76 s 降到 0.715 s（缓存命中）／4.56 s（强制联网）。
- **毒缓存自愈**：缓存表解析出 0 条目或缺必需接口时自动丢弃并重取一次；远端坏表则明确报错。
- **下载失败分级**：传输故障每镜像重试一次，404 不重试；只有整条镜像链都 404 才判定「上游未发布」。
- **镜像链补第二活源** `mmxlyo/steam-monitor`，排在 `git.lua.tools` 之后。
- **签名表懒刷新**：缓存命中但确有函数查不到时，后台异步重取一次（每模块每会话最多一次），不阻塞启动，新表下次启动生效。
- **弹窗**：全部改为中文并指向本仓库；编码改用 `MessageBoxW`（此前中文乱码），并按线程 DPI 上下文绘制（此前边缘发虚）；文案统一为书面表述。

## 修复

**入库与许可**

- 许可包的 AppID 向量扩容后回写长度：注入的 depot 现在对按长度遍历的逻辑可见，「删除 lua」也能真正把条目摘净（此前静默空转）。
- 包 0 注入去重，移除时一次摘净：热重载的「先加后删」不再留下残影。
- 应用返回 0 个 depot 时判定失败，避免把空 depot 配置写下去（此前表现为「入库后瞬间完成 / 0 mounted depots」）。
- 家庭共享与已被移除应用的判定：lua 变更不再让共享游戏从库中消失。

**票据与密钥**

- 伪造票供体改为梯度：`228980` → `480` → `7`，首个有票者胜出（此前固定 AppId 7，7 的票缺失即整条失败 → 54）。
- 交付前校验票据长度（下限 20 字节）与签名边界，坏票不再按正常偏移交给游戏（→ 54）。
- 密钥读取改用 `from_chars`，键名异常时不再从钩子抛异常进 steamclient；键名兼容 `/` 分隔。
- 票据扩展数据响应前先校验缓冲容量，容量不足时扩容，不再因 steamclient 返回最小失败响应而静默丢弃补丁。
- ConfigStore 指针改为原子读写（此前跨线程裸读写）。
- 在线铸造失败时清掉本会话内该应用的旧 eticket（旧票绑旧 nonce → 88500012）。

**报文与界面**

- 头部长度改为减法比较，消除 uint32 回绕导致的越界读。
- 清单取码的异步结果加异常保护，异常不再穿过收包钩子。
- 云待投递队列满时丢弃最旧一条（此前静默丢新包，对应 RPC 永久挂起）。
- 库移除时的变更通知仅在应用对象存在后发出（此前会触发未初始化断言）。

**稳定性**

- Detours 事务失败即回滚，Attach 失败清掉句柄；卸载后不再残留「看起来已装上」的假状态。
- 进程退出时跳过 DLL 清理（此时次级线程已被系统终止，等待它们会挂死）。
- 目录监听改为跨线程取消并等待读取结束，修复退出或重载瞬间的释放后使用。
- 覆盖层、崩溃上报、Steamworks 运行库等伴生进程拉起时，不再清除联机会话状态。
- Steam 安装目录改为按宿主进程的路径定位，不再依赖当前工作目录；两个代理垫片加固（重复加载幂等、按自身目录绝对路径加载、加载失败不再连累宿主）。

## 已知限制

- **联机**：大厅层可用，P2P 传输层在本机环境下建不起连接（未测到中继节点）。相关诊断已挂起。
- **卡普空新作**：其完整性校验会扫描 Steam 侧模块，直接 hook 原版 `steamclient64.dll` 会被判定异常而闪退。当前版本未做影子模块隔离。
- **通过第三方启动器启动的游戏**（育碧 / Epic / Rockstar）：需在 lua 里配 `addprocess`，Denuvo 游戏必要时配 `forcedenuvo`。
- **密钥覆盖**：Sudama 未收录的 depot 无法补齐（例如 X4 的 942198），下载会在初始化阶段中止。

## 升级方式

覆盖 Steam 根目录下的三个 DLL：`OpenSteamTool.dll`、`dwmapi.dll`、`xinput1_4.dll`。覆盖前请自行备份原文件。

配置模板 `opensteamtool.toml` 可整体替换（新增 `[presence]` 段）；若你改过配置，保留原文件即可，缺少的段会按默认值工作。
